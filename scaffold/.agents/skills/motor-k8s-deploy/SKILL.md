# motor-k8s-deploy

Use `remote.bash` on the selected endpoint and the fixed Motor source tree. Do
not use workspace wrapper scripts or local run IDs.

## Deploy

After a successful dry-run, show the exact endpoint, context, config directory,
namespace, and command. Obtain explicit consent, then run:

```bash
cd /mnt/motor-workspace/motor/examples/deployer
python3 deploy.py --config_dir <remote-config-dir>
```

Use the upstream command's exit status and then inspect real resources:

```bash
kubectl --context "$CTX" get all -n "$NS"
kubectl --context "$CTX" get pods -n "$NS" -o wide
kubectl --context "$CTX" get events -n "$NS" --sort-by=.lastTimestamp
```

Wait only for the workload kinds actually generated by the native deployer.
Verify Pod `Ready`, service endpoints, and—when code replacement matters—the
runtime package `__file__` paths with `kubectl exec`.

## Status

Status is read-only. Query current workloads, Pods, Services, endpoints,
events, and selected logs. Do not infer success from old local evidence.

## Restart

Obtain explicit consent, discover the concrete Deployments/StatefulSets, then
restart only those targets and wait for rollout. Never use `--all`.

- Controller/Coordinator debug loop: changed `yaml_template` and/or
  `user_config` and/or a component-only wheel, and P/D must keep running.
  Follow `../../../docs/controller-coordinator-debug-rollout.md`. Never run
  full `deploy.py` or `--update_config` for this path.
- Single live ConfigMap JSON field only: follow
  `references/component-config-rollout.md` and restart only that component.

## Stop

Obtain explicit consent and show the namespace/resources first. Prefer the
source tree's `examples/deployer/delete.sh`; otherwise delete only the exact
generated manifest files. Never delete a namespace or unrelated resources.

Report commands and observed cluster state directly. Deployment success means
the native command succeeded and the required current workloads are Ready;
Coordinator readiness still belongs to `motor-smoke`.
