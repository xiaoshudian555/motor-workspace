# Routing Topology 证明请求在目标拓扑中走到正确实例和角色

## 负责

- 验证 PD 分离、PD 混部及明确支持的其他目标拓扑。
- 验证 Prefill、Decode、hybrid 和多实例条件下的请求分配。
- 验证 scheduler 策略、实例负载和可用状态对路由选择的影响。
- 验证 KV Cache affinity、重复前缀和冷热缓存场景的路由行为。
- 验证扩缩容、实例摘除与恢复前后的流量迁移。
- 将客户端请求与实例级 metrics、日志或 tracing 关联，证明实际路由结果。

## 完成标准

指定 workload 下，实际实例/角色选择符合场景预期；实例状态变化后，路由表和
流量分配能收敛到目标状态，且没有不可接受的丢请求、重复响应或卡死。

## 不负责

- 执行部署 apply 或直接修改实例数。
- 单独判断模型输出精度。
- 仅凭最终请求成功推断路由一定正确。

## 交付

`routing-topology` validation run，包括拓扑、scheduler 配置、特征化 workload、
实例选择证据、状态变化时间线和判定结果。
