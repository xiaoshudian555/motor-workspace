# Correctness 证明协议、token、输出和模型精度没有被破坏

## 负责

- 验证 OpenAI-compatible 响应字段、SSE 分片、结束条件和错误语义（协议正确性）。
- 在固定输入、固定配置和可控随机性的条件下比较输出或 token 序列（推理一致性）。
- 验证 PD 协作、KV Cache 传输、sampling、量化或其他特性没有引入输出错误。
- 在需要时执行目标模型和数据集的 accuracy evaluation（模型精度）。
- 区分协议正确性、推理一致性和模型精度，分别给出判定。

## 完成标准

执行环境、基线、容差或评分规则明确；实际结果满足声明的比较规则，并保存可
复核的原始输出和聚合结果。

## 不负责

- 仅以“请求返回 HTTP 200”判定正确。
- 用性能指标代替正确性结论。
- 在未固定影响输出的输入和配置时声称结果发生回归。
- 验证特性开关的业务生效方式（例如 API key 拒识、metrics 暴露）；该责任属于
  [`../functional/`](../functional/)。
- 用 smoke 的最小 HTTP/SSE 断言代替本场景的完整协议/一致性/精度结论；smoke
  只提供 gate 级子集。

## 交付

`correctness` validation run，包括数据集或 case 版本、随机性配置、基线引用、
逐项结果、聚合分数、容差和判定。失败时引用
[`../../diagnosis/`](../../diagnosis/)。
