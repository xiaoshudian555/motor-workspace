# Stability 证明服务长时间运行不会泄漏、漂移或积累错误状态

## 负责

- 在固定或代表性 workload 下进行长时间运行验证。
- 观察成功率、尾延迟、吞吐和队列状态是否随时间漂移。
- 观察 CPU、内存、NPU HBM、连接、线程、文件句柄等资源是否持续增长。
- 验证 metrics、日志和 tracing 在长时间运行中持续可用。
- 验证多轮请求、重启或扩缩容后没有积累脏状态。

## 完成标准

运行时长和 workload 由场景显式声明；关键业务指标和资源时间序列完整，没有
超过阈值的持续漂移、泄漏或不可恢复异常。

## 不负责

- 用短时间 benchmark 推断长稳结果。
- 主动注入硬件或组件故障；该责任属于
  [`../reliability/`](../reliability/)。
- 把有意扩缩容后的路由收敛当作本场景主责；routing 验收属于
  [`../routing-topology/`](../routing-topology/)，本场景只观察长稳副作用
  （例如重启或扩缩容后是否积累脏状态）。
- 在没有时间序列证据时仅凭最终服务存活判定通过。

## 交付

`stability` 证据目录包括 workload、观测周期、业务与资源时间序列、
异常事件、趋势判定和 [`../../diagnosis/`](../../diagnosis/) 引用。
